# AXIS Video — как здесь работать

SMMAKER (бывший AXIS Video) — SaaS для видео и постов автодилеров: реклама, обзоры, карусели.
Компании регистрируются сами, получают пробные кредиты и докупают пакеты; с базой (`DATABASE_URL`) —
вход обязателен, без базы — один владелец без входа (тесты, прод до выкладки кабинетов).
Всё общение, комментарии в коде и сообщения коммитов — **по-русски**.

## Документы и что в них

| файл | о чём | когда читать |
|---|---|---|
| **CONTEXT.md** | зачем всё устроено именно так, решения с причинами, где легко ошибиться, замеры | перед любой правкой, затрагивающей поведение |
| **README.md** | что умеет инструмент и как им пользоваться | когда нужен обзор возможностей |
| этот файл | правила работы и грабли, на которых уже спотыкались | всегда |

**Держи их в актуальном состоянии.** Поменял поведение — поправь CONTEXT.md; поменял то, что
видит пользователь, — поправь README.md. Проект растёт, и расхождение документации с кодом
дороже, чем минута на правку.

## Три пайплайна

**Реклама авто** — ролик из фотографий лота с ценой. 1080×1920, 30 кадров, формат описан
в `config/formats.json`, вёрстка в `src/formats/`.

**Обзоры авто** — монтаж своей вертикальной съёмки. 1080×1920, **60 кадров**. Композиция
`src/reviews/ReviewShort.tsx`, раскладка `src/shared/timeline.js`.

**Карусели авто** — слайды по объявлению Encar для Instagram и TikTok в одном из форматов
`config/carousel-formats.json` (7×9:16, 9×1:1, 6×4:5, 12×1:1), на английском или русском.
Композиция `src/carousel/` («Классика» — `Carousel.tsx`, остальные — `deck/`), данные через
шлюз в соседнем проекте kmotors.

## Запуск

```bash
npm run app                 # http://localhost:3210
./tools/restart.sh          # перезапуск — только так, см. ниже
npm run build               # собрать интерфейс — нужно только для боя и контейнера
docker build -t axis-video .
```

## Грабли, на которых уже спотыкались

**Перезапускай только через `tools/restart.sh`.** Правки в `server/` подхватываются лишь
перезапуском, а `pkill` со сном не гарантирует ничего: порт остаётся занят, новый процесс
падает в фоне, health-check отвечает — потому что отвечает прежний сервер. На этом за один
день трижды был сделан ложный вывод «правка не работает».

**`npm test` НЕ гоняет рендер-тесты.** Они отдельной командой `npm run test:render` и идут
минуты. После перехода обзоров на 60 кадров их не запускали, и внутри осталось деление на 30.
Перед коммитом, трогающим композиции или таймлайн, прогоняй **оба** набора.

**Всё, что зависит от частоты, бери из `REVIEW_FPS`.** Числом не пиши: смена частоты
сломает это молча.

**Тайминги оформления — в секундах, не в кадрах** (`atSec`). При переходе на 60 кадров всё
оформление пошло вдвое быстрее, и затемнение читалось как обрыв съёмки.

**`FFMPEG_PATH` на свою сборку ставить нельзя.** В сборке Homebrew нет фильтра `zscale`,
на котором держится перевод HDR — копия соберётся без него, и картинка выйдет вялой.
Полный ffmpeg годится для замеров, но не для подготовки копии.

**Рендер без ошибок ничего не доказывает.** Дважды фразы молча пропадали из готового ролика,
и оба раза сборка завершалась успешно. Проверяй по файлу: вытащи дорожку и прогони через
распознавание, картинку — посчитай разницей между соседними кадрами.

**Instagram обрезает слайды карусели.** Он не поддерживает 9:16 и режет до 4:5 — по 285
пикселей сверху и снизу. Весь текст обязан жить внутри `SAFE`, фото может выходить за неё.
Проверяй правки обрезанной копией: `ffmpeg -i slide.png -vf "crop=1080:1350:0:285" ig.png`.

**Статика в бою включается по `NODE_ENV=production`, а не по наличию `dist/`.** Соблазн
проверять папку велик, но тогда один `npm run build` на Mac молча выключит горячую
перезагрузку, и правки в интерфейсе перестанут появляться без единого сообщения. В обратную
сторону наоборот строго: нет сборки при `NODE_ENV=production` — падаем на старте.

**На сервере ставь `RENDER_CONCURRENCY=2`.** Замер: при 8 рендер ест 2372 МБ, при 2 —
889 МБ, а время почти то же (27 с против 30). Память растёт линейно по потокам, скорость —
нет. На машине с боевым сайтом восьмёрка не поместится.

**Превью и рендер берут данные из разных мест.** Превью считается в браузере из формы, рендер
получает обзор от сервера. Новое поле, которое сервер не умеет сохранять, в превью видно,
а в ролике нет — и выглядит это как «настройка не применяется».

**Данные прода живут в томе Coolify `smmaker-data` (Persistent Storage → `/app/data`).** Без него
каждая выкладка давала контейнеру новый пустой том — так уже терялись данные. Меняешь
настройки приложения в Coolify — проверь, что том на месте.

**Пуш в `main` — это деплой на прод.** Боевой инструмент развёрнут через Coolify с автосборкой
по вебхуку: каждый `git push` в `main` пересобирает и подменяет контейнер на публичном домене
(`*.sslip.io`, за Basic Auth). Не сырой код в `main`. Ручной `tools/vps-deploy.sh` теперь
**не использовать** — он поднимал отдельный контейнер, а владелец деплоя — Coolify; запуск
скрипта создаст дубль.

**Бренд и профиль компании живут в базе, если задан `DATABASE_URL`.** Тогда `config/brand.json`
и `config/profiles/` читаются один раз — при заведении компании — и дальше правда в
`smmaker_workspaces`; правка файла в `config/` уже ничего не меняет. Без базы (тесты, прод до
подключения) — по-старому из `config/`, и на проде такую правку смывает передеплой.

**Файлы компании — в `data/workspaces/<компания>/`, не в `data/`.** Лоты, обзоры, ролики,
карусели, логотипы. Адреса строй от `workspaceDir()` / `workspaceUrl()` из `server/store.mjs`,
не пиши `/data/lots/…` руками и не заводи констант с путём компании: компания — свойство
**запроса** (`withWorkspace`), константа на загрузке модуля навсегда зашила бы одну.
Новый обработчик — через `wrap` (он ставит компанию); фоновая работа, которая стартует
не из своего запроса (как очередь рендера), обязана нести компанию с собой.

**Новая генерация — только за кредиты.** Всё, что создаёт ролик, карусель или тратит
внешний сервис, закрыто `requireCredits` и списывает кредиты: через очередь —
`enqueue({..., bill})`, синхронно — `billed(...)` из `server/billing.mjs`. Исход обязан
закрыть списание: `settle` при успехе, `refund` при ошибке или отмене. Цены —
`config/credits.json`. Кредиты лежат партиями со сроком (`smmaker_credit_lots`): счётчик
в одну цифру не заводи — у бесплатных, пакетов и бонусов разные сроки.

**С базой включается вход.** На Mac после `DATABASE_URL` в интерфейс без входа не попасть:
`npm run admin -- почта` заводит владельца. Тесты входа — `tests/server/auth.test.mjs`,
идут только с `TEST_DATABASE_URL` на свой Postgres (не общий Supabase). Старую раскладку переносит `tools/migrate-workspace.mjs`
(без `--apply` — только показывает); сервер при старте предупреждает, если она осталась.

**Без туннеля к базе сервер на Mac не стартует.** Mac уснул — туннель умер:
`ssh -f -N -L 54329:<адрес>:5432 axis-vps` (запускает владелец), потом `tools/restart.sh`.
Адрес контейнера базы меняется при перезапуске Supabase (27.09: 10.0.2.6 → 10.0.2.2) — узнать:
`docker inspect -f '{{range $k,$v := .NetworkSettings.Networks}}{{$k}}={{$v.IPAddress}} {{end}}' supabase-db-o6sghkg5pktjad44oaigyy7h`.

**Redeploy сервиса Supabase в Coolify нажимать нельзя** — он останавливает все контейнеры и падает
на образе `minio/mc` (удалён из Docker Hub), kmotors остаётся без базы. Сеть `coolify` к базе
подключена вручную (`docker network connect`) — слетит, если контейнеры Supabase пересоздадут.

**Всё в базе, что наше, называется `smmaker`.** Supabase общий с kmotors и caranalizer.
Схема `smmaker` (прод) или `smmaker_dev` (Mac), таблицы и индексы — `smmaker_…`, ходим под
`smmaker_app`. Новая таблица без префикса не пройдёт `npm test`. Чужое в этом Supabase не
трогать. Схема меняется только новой миграцией `server/db/migrations/NNN_имя.sql` —
старые не правь, они уже применены. Подробно — CONTEXT.md, «База SMMAKER».

## Правило про комментарии

Комментируй **почему**, а не «что». «Увеличиваем счётчик» писать не надо — видно и так.
А вот почему тут `Math.floor`, а не `round`, почему цифра именно 0,12 и что сломается, если
её поменять, — надо: через месяц это неочевидно даже автору.

Особенно комментируй: подобранные на замерах числа (с самим замером), обходы чужих
странностей, и места, где очевидное решение неверно — с объяснением, почему.

## Что не коммитить

`data/` (исходники, копии, рендеры), `.env`, `.venv-demucs`. Всё уже в `.gitignore` —
проверяй, что не добавил лишнего: одна команда `git add -A` уже затаскивала 5 МБ мусора.

## Внешние зависимости

| что | зачем | ключ |
|---|---|---|
| ElevenLabs | распознавание речи, озвучка | `ELEVENLABS_API_KEY` |
| шлюз kmotors | данные Encar для каруселей | `KMOTORS_API_URL`, `KMOTORS_API_SECRET` |
| Demucs | звуки машины без голоса (проба) | окружение `.venv-demucs`, необязательно |
| Resend | письма: код подтверждения почты, сброс пароля | `RESEND_API_KEY`, `RESEND_FROM`, `SMMAKER_APP_URL` |
| Postgres (общий Supabase) | база SMMAKER: кабинеты, пакеты, кредиты | `DATABASE_URL`, `SMMAKER_DB_SCHEMA` |

Шлюз живёт в соседнем проекте `~/Desktop/recup/KMotors-1`: `src/app/api/vehicle/[id]/route.ts`.
Оттуда же русский словарь карусели — `tools/sync-kmotors-dict.mjs`. Encar режет
адреса дата-центров, поэтому ходим через него, а не напрямую.
