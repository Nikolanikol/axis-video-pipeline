# AXIS Video — как здесь работать

SMMAKER (бывший AXIS Video; клиенту — **KOK**, «Контент одной кнопкой») — SaaS для видео и постов автодилеров: реклама, обзоры, карусели.
Компании регистрируются сами, получают пробные кредиты и докупают пакеты; с базой (`DATABASE_URL`) —
вход обязателен, без базы — один владелец без входа (тесты, прод до выкладки кабинетов).
Всё общение, комментарии в коде и сообщения коммитов — **по-русски**.

## Документы и что в них

| файл | о чём | когда читать |
|---|---|---|
| **CONTEXT.md** | зачем всё устроено именно так, решения с причинами, где легко ошибиться, замеры | перед любой правкой, затрагивающей поведение |
| **README.md** | что умеет инструмент и как им пользоваться | когда нужен обзор возможностей |
| этот файл | правила работы и грабли, на которых уже спотыкались | всегда |

**Держи их в актуальном состоянии.** Поменял поведение — поправь CONTEXT.md; поменял то, что
видит пользователь, — поправь README.md. Проект растёт, и расхождение документации с кодом
дороже, чем минута на правку.

## Три пайплайна

**Реклама авто** — ролик из фотографий лота с ценой. 1080×1920, 30 кадров, форматы («Авто с
ценой», «Галерея», «Цена сразу») описаны в `config/formats.json`, вёрстка в `src/formats/`.
Основной путь — три действия: вставить ссылку Encar → «Собрать» → «Скачать»
(`app/ads/QuickLot.tsx`), ручное — под «Изменить вручную».

**Обзоры авто** — монтаж своей вертикальной съёмки. 1080×1920, **60 кадров**. Композиция
`src/reviews/ReviewShort.tsx`, раскладка `src/shared/timeline.js`.

**Карусели авто** — слайды по объявлению Encar для Instagram и TikTok в одном из форматов
`config/carousel-formats.json` (7×9:16, 9×1:1, 6×4:5, 12×1:1), на английском или русском.
Композиция `src/carousel/` («Классика» — `Carousel.tsx`, остальные — `deck/`), данные через
шлюз в соседнем проекте kmotors.

## Порядок разработки: сначала превью, потом прод

С 11.10 на проде живые клиенты, поэтому **ничего не идёт в `main` напрямую**. Каждая задача:

1. **Своя ветка от свежего `main`:** `feat/<что>` — новое, `fix/<что>` — исправление,
   `docs/<что>` — только документация. Одна задача — одна ветка.
2. **Локальная проверка владельцем.** Сделал — тесты, сервер на :3210 перезапущен, рассказал,
   что смотреть. Владелец сам проверяет руками и глазами. **Коммит, push и PR — только когда он
   скажет** (правило с 11.10: сам открыл два PR без спроса — так не надо).
3. **Push ветки и Pull Request в `main`** (`gh pr create`). Coolify сам поднимает превью
   `https://<номер PR>.preview.axis-beauty.com` — метка «ТЕСТ · PR N», своя схема базы
   `smmaker_preview`, свой том. Каждый следующий push в ветку обновляет превью сам (3–4 мин).
4. **Проверка на превью** — моя (страница, телефон, консоль) и владельца.
5. **Merge PR в `main` — только по слову владельца.** Merge = выкладка на прод
   (Auto Deploy). После merge превью удаляется само.

Что куда пушить:
- в ветку задачи — после локальной проверки и слова владельца; дальше правки по превью — по его же слову;
- в `main` — никогда напрямую, только merge проверенного PR с OK владельца;
- срочное исправление прода — тоже через `fix/…` и превью, просто быстрее.

Превью узнаёт себя по имени контейнера `…-pr-N` (`previewId` в `server/db/index.mjs`) и
**не стартует на боевой схеме `smmaker`**. Не ослабляй эту страховку и не узнавай превью по
`COOLIFY_BRANCH` — там `main`. Аккаунт для проверки в превью — тестовый, общий для всех PR
(одна схема). Настройка превью и ловушки Coolify — CONTEXT.md, «Превью веток в Coolify».
Данные превью — **копия** прода (`tools/db/preview-copy.sql`, владелец запускает в Studio), не сам
прод. У превью нет `RESEND_API_KEY` — не возвращай: в копии почты живых клиентов. Несколько PR
вместе посмотреть — общая ветка `feat/preview-all` (CONTEXT.md, тот же раздел).

## Грабли, на которых уже спотыкались

**Перезапускай только через `tools/restart.sh`.** Правки в `server/` подхватываются лишь
перезапуском, а `pkill` со сном не гарантирует ничего: порт остаётся занят, новый процесс
падает в фоне, health-check отвечает — потому что отвечает прежний сервер. На этом за один
день трижды был сделан ложный вывод «правка не работает».
Агенту — не из своего Bash: процесс-потомок esbuild умирает вместе с командой, `/healthz`
и API отвечают, а страница не собирается («The service is no longer running»). Сервер
запускать во вкладке терминала (`npm run app`) и проверять саму страницу, а не только
`/healthz`.

**`npm test` НЕ гоняет рендер-тесты.** Они отдельной командой `npm run test:render` и идут
минуты. После перехода обзоров на 60 кадров их не запускали, и внутри осталось деление на 30.
Перед коммитом, трогающим композиции или таймлайн, прогоняй **оба** набора.

**Границы фраз озвучки — `cutFrom/cutTo` по звуку, а не `from/to` разметки.** Играй и режь по
`clipOf` (он отдаёт уточнённые), а слитность строк определяй по `rawFrom/rawTo`/`joinedNext`:
запас тишины смыкает границы, и по ним обычную паузу приняли бы за слитную речь. Менял
`voicePlan` или `clipOf` — прогони `npm test` и `npm run test:render`. Встроенный ffmpeg
Remotion умеет только WAV: сырой `s16le` и `flac` он не пишет.

**kmotors.shop закрыт из Кореи целиком** (403, в том числе `/api/vehicle`). Лоты аукционов
(`server/kmotorsLot.mjs`) локально берутся из образцов: `KMOTORS_LOT_FIXTURES=tests/fixtures/kmotors-lots`;
живые страницы — только с сервера в Германии или через `office.kmotors.shop` (Cloudflare Access,
нужен сервисный токен). Ломается разбор страницы — сними образец заново с немецкого сервера
(одним запросом на площадку, с паузой), не ходи в carnect напрямую.

**Всё, что зависит от частоты, бери из `REVIEW_FPS`.** Числом не пиши: смена частоты
сломает это молча.

**Тайминги оформления — в секундах, не в кадрах** (`atSec`). При переходе на 60 кадров всё
оформление пошло вдвое быстрее, и затемнение читалось как обрыв съёмки.

**`FFMPEG_PATH` на свою сборку ставить нельзя.** В сборке Homebrew нет фильтра `zscale`,
на котором держится перевод HDR — копия соберётся без него, и картинка выйдет вялой.
Полный ffmpeg годится для замеров, но не для подготовки копии.

**Рендер без ошибок ничего не доказывает.** Дважды фразы молча пропадали из готового ролика,
и оба раза сборка завершалась успешно. Проверяй по файлу: вытащи дорожку и прогони через
распознавание, картинку — посчитай разницей между соседними кадрами.

**Instagram обрезает слайды карусели.** Он не поддерживает 9:16 и режет до 4:5 — по 285
пикселей сверху и снизу. Весь текст обязан жить внутри `SAFE`, фото может выходить за неё.
Проверяй правки обрезанной копией: `ffmpeg -i slide.png -vf "crop=1080:1350:0:285" ig.png`.

**Статика в бою включается по `NODE_ENV=production`, а не по наличию `dist/`.** Соблазн
проверять папку велик, но тогда один `npm run build` на Mac молча выключит горячую
перезагрузку, и правки в интерфейсе перестанут появляться без единого сообщения. В обратную
сторону наоборот строго: нет сборки при `NODE_ENV=production` — падаем на старте.

**На сервере `RENDER_CONCURRENCY=4`** (с 13.10, сервер 8 ядер / 16 ГБ, у KOK лимит 6 ГБ / 6 ядер).
Каждая вкладка — свой процесс браузера, память растёт линейно (на M1: 2 — 889 МБ, 8 — 2372 МБ),
а скорость после 4 почти не растёт (замер на сервере: 4 — 17,4 кадра/с, 6 — 16,4). Подробно —
CONTEXT.md, «Скорость рендера на сервере».

**Не ставь `filter: blur(…)` на то, что рисуется в каждом кадре ролика.** На сервере нет
видеокарты, и размытие фона 1240×2080 браузер считал процессором на каждом кадре: рендер шёл
вдвое медленнее (6,2 против 12,6 кадра/с), а превью на телефоне подтормаживало. Размытый фон
фото готовится один раз на сервере (`photos/bg/`, `Backdrop` в `src/shared/ui.tsx`); новое
размытие — так же, заранее. Исключение пока — фон обзора (`ReviewShort`, размытое видео).

**Превью и рендер берут данные из разных мест.** Превью считается в браузере из формы, рендер
получает обзор от сервера. Новое поле, которое сервер не умеет сохранять, в превью видно,
а в ролике нет — и выглядит это как «настройка не применяется».

**Данные прода живут в томе Coolify `smmaker-data` (Persistent Storage → `/app/data`).** Без него
каждая выкладка давала контейнеру новый пустой том — так уже терялись данные. Меняешь
настройки приложения в Coolify — проверь, что том на месте.

**Пуш в `main` — это деплой на прод.** Боевой инструмент развёрнут через Coolify с автосборкой
по вебхуку: каждый `git push` в `main` пересобирает и подменяет контейнер на
`https://app.axis-beauty.com`, где работают клиенты. Поэтому в `main` — только через PR и
превью (раздел «Порядок разработки» выше). Ручной `tools/vps-deploy.sh` теперь
**не использовать** — он поднимал отдельный контейнер, а владелец деплоя — Coolify; запуск
скрипта создаст дубль.

**Бренд и профиль компании живут в базе, если задан `DATABASE_URL`.** Тогда `config/brand.json`
и `config/profiles/` читаются один раз — при заведении компании — и дальше правда в
`smmaker_workspaces`; правка файла в `config/` уже ничего не меняет. Без базы (тесты, прод до
подключения) — по-старому из `config/`, и на проде такую правку смывает передеплой.

**Файлы компании — в `data/workspaces/<компания>/`, не в `data/`.** Лоты, обзоры, ролики,
карусели, логотипы. Адреса строй от `workspaceDir()` / `workspaceUrl()` из `server/store.mjs`,
не пиши `/data/lots/…` руками и не заводи констант с путём компании: компания — свойство
**запроса** (`withWorkspace`), константа на загрузке модуля навсегда зашила бы одну.
Новый обработчик — через `wrap` (он ставит компанию); фоновая работа, которая стартует
не из своего запроса (как очередь рендера), обязана нести компанию с собой.

**Новая генерация — только за кредиты.** Всё, что создаёт ролик, карусель или тратит
внешний сервис, закрыто `requireCredits` и списывает кредиты: через очередь —
`enqueue({..., bill})`, синхронно — `billed(...)` из `server/billing.mjs`. Исход обязан
закрыть списание: `settle` при успехе, `refund` при ошибке или отмене. Цены —
`config/credits.json`. Кредиты лежат партиями со сроком (`smmaker_credit_lots`): счётчик
в одну цифру не заводи — у бесплатных, пакетов и бонусов разные сроки.

**С базой включается вход.** На Mac после `DATABASE_URL` в интерфейс без входа не попасть:
`npm run admin -- почта` заводит владельца. Тесты входа — `tests/server/auth.test.mjs`,
идут только с `TEST_DATABASE_URL` на свой Postgres (не общий Supabase). Старую раскладку переносит `tools/migrate-workspace.mjs`
(без `--apply` — только показывает); сервер при старте предупреждает, если она осталась.

**Без туннеля к базе сервер на Mac не стартует.** Mac уснул — туннель умер:
`ssh -f -N -L 54329:<адрес>:5432 axis-vps` (запускает владелец), потом `tools/restart.sh`.
Адрес контейнера базы меняется при перезапуске Supabase (27.09: 10.0.2.6 → 10.0.2.2) — узнать:
`docker inspect -f '{{range $k,$v := .NetworkSettings.Networks}}{{$k}}={{$v.IPAddress}} {{end}}' supabase-db-o6sghkg5pktjad44oaigyy7h`.

**Почта уходит только с подтверждённого домена.** Отправитель `RESEND_FROM` — на
`mail.axis-beauty.com` (имя отправителя — KOK; отдельный аккаунт Resend под SMMAKER, DNS в Cloudflare). Сменишь
отправителя на другой домен — Resend ответит 403, и регистрация останется без кода. Записи
DNS добавляй только на поддоменах: корень `axis-beauty.com` — чужой сайт на Vercel.

**Redeploy сервиса Supabase в Coolify нажимать нельзя** — он останавливает все контейнеры и падает
на образе `minio/mc` (удалён из Docker Hub), kmotors остаётся без базы. Сеть `coolify` к базе
подключена вручную (`docker network connect`) — слетит, если контейнеры Supabase пересоздадут.

**Телефон (до 900 px) — отдельная раскладка, проверяй её на каждой правке интерфейса.**
Экран 375×812 в панели браузера (`resize_window` mobile) и ширина страницы: `scrollWidth`
должен быть ровно 375. Грабли, на которые уже наступали:
- колонка сетки — только `minmax(0, 1fr)`: у `1fr` нижняя граница — ширина содержимого, и
  одна длинная строка (список правил логотипа, миниатюры слайдов) растягивала экран вбок;
- шрифт в `input`/`select`/`textarea` — не меньше 16 px: иначе iPhone приближает страницу при
  касании поля. Своё правило поля с меньшим размером (`.lots-tools select`) перебивает общее;
- разделы телефона (`app/MobileTabs.tsx`): «Ролик»/«Карусель» — дом, «Объявления» и «Правка» —
  панели `position: fixed` поверх, переключаются кнопками и свайпами. Верх панелей — `--mtop`,
  он меряется сам; шапку и нижнюю панель не меняй, не пересчитав высоту превью
  (`calc(100dvh - 240px …)` в styles.css);
- плеер Remotion не держи в скрытом разделе и за экраном: играет и рисует 1080×1920 впустую —
  прокрутка подлагивает. `Preview` сам встаёт на паузу вне экрана, на телефоне плеер
  монтируется только в «Ролике»;
- HTML5-перетаскивание на тач-экранах не работает — там касания (`Photos` в `LotForm.tsx`);
- листаемое пальцем — лентой, а не подменой картинки: элементы в ряд, лента идёт за пальцем
  и доезжает при отпускании (`useSlideTrack` и `SlideTrack` в `CarouselTool.tsx`). Владелец
  отверг вариант «сдвинул картинку — она сменилась»;
- оверлей во весь экран (лайтбокс) закрывается и нажатием мимо: внутренний блок не должен
  глотать клик, а картинка — тянуться шире своего кадра;
- в скрытой панели браузера CSS-анимации и `IntersectionObserver` не идут: проверяя панели,
  отключай переходы (`*{transition:none}`), иначе они «застывают» на полпути и тест врёт.
- плитки-кнопки с `aspect-ratio` в сетке с ограниченной высотой и прокруткой Safari на iPhone сплющивает
  (Chrome и его эмуляция — нет; 13.10, фото Encar в «Правке»). Пропорцию там держи отступом
  (`height: 0; padding-bottom: 75%`), картинку — абсолютно поверх; проверка — только на настоящем iPhone.

**Логотипы площадок — `app/Sources.tsx` (13.10).** Витрина, шапка рабочих экранов (от 1280 px), строка под
полем ссылки (до 1279 px), подвал. Новый источник — строка в `SOURCES` и PNG в `public/sources/`. Подробно —
CONTEXT.md, «Площадки-источники на экранах».

**Витрина гостя — `app/Landing.tsx`, образцы — статика в `public/landing/`.** Образцы собирает
`node --env-file=.env tools/landing-samples.mjs` (нужны копия на :3211 и шлюз kmotors);
меняешь вёрстку роликов или каруселей заметно — пересобери, иначе витрина покажет старый
вид. Только демо-компания «Ваша компания» (`src/shared/landingDemo.js`): работы настоящих
клиентов на публичной странице — только с их согласия. Условия гостю отдаёт
`GET /api/public/offer` (до `requireUser`): не добавляй туда ничего, чего нельзя показать
любому. Без базы витрина — по `#/welcome`.
Превью в настройках у клиента без объявлений — своё демо-объявление `public/preview-demo/` (Ford F-150,
Encar 40303537, выбор владельца 12.10), не витринная Kona: их меняют независимо. Заслонки Basic Auth больше нет (снята 11.10) — не возвращай.

**Поисковики — `server/seo.mjs`, тексты — `config/seo.json` (19.10).** Страницу собирает сервер
(`renderPage`), гостю на «/» — готовая витрина из `npm run build` (`tools/prerender.mjs`). Меняешь
вопросы витрины — только в `config/seo.json` (их же берёт разметка FAQPage). В поиск пускается
только боевой адрес — не ослабляй проверку `isPrimary`: превью с копией прода попадут в Google.
Новый счётчик или трекер — только через согласие (`app/analytics.tsx`) и с правкой политики.

**Подвал — один на витрину и рабочие экраны (`app/SiteFooter.tsx`, 12.10).** В кабинете он стоит под
`.app` — рабочей зоной ровно в высоту экрана (`100dvh`), прокручивается документ: работе не мешает, до
подвала — чуть прокрутить. Не ставь `.app` обратно `height: 100%` и не клади подвал внутрь `.tool`.
На телефоне в инструментах с выдвижными панелями (`PHONE_PANEL_TOOLS` в `Shell.tsx`) подвала нет:
панели, вкладки и кнопка сборки закреплены поверх экрана. Новый такой инструмент — добавь туда.

**«Первые шаги» (`app/Onboarding.tsx`) отмечают шаги по данным.** Меняешь, где хранится
название компании, контакты, логотип или как считаются объявления — проверь `useOnboarding`,
иначе галочка молча перестанет ставиться. Регистрация ведёт на `#/start`.

**Личный кабинет (`#/account`, 12.10) — `app/Account.tsx`, `AccountProfile.tsx`, `AccountPlans.tsx`.**
Подробно — CONTEXT.md, «Профиль и безопасность в кабинете». Что легко сломать:
- **Телефон клиент сам не меняет** — номер держит бесплатные кредиты; `PUT /account/profile` поле
  `phone` не читает. Не возвращай поле телефона в форму без решения владельца.
- **Компания одна — `profile.company`.** `smmaker_workspaces.name` (шапка, админка) идёт за ней: его
  пишут и `updateAccount`, и `saveProfile`. Второго «названия кабинета» не заводи.
- **Почта и пароль — только с текущим паролем, ответ 403, не 401**: 401 интерфейс понимает как
  «вход слетел» и перезагружает страницу (`request` в `app/api.ts`).
- **Удаление — отложенное на 14 дней** (`delete_after`): `readSession`, `login` и `requestReset` такой
  аккаунт не пускают. Новый способ войти (вход через Google и т. п.) обязан проверять `delete_after`.
  Окончательно чистит `purgeDeleted` (таймер в `server/index.mjs`); строки компании, партий и журнала
  **не удаляются** — обезличиваются (расчёты хранят 5 лет), поэтому не ставь `ON DELETE CASCADE` в расчёт
  на удаление компании.
- **Цифры тарифов — только из базы** (`smmaker_packs`), «−N%», «выгоднее всего», «≈ роликов» считает
  `AccountPlans.tsx`. В коде цен нет: на Mac (`smmaker_dev`) они могут отличаться от прода — это данные,
  а не баг вёрстки.
- **Движение (`.lift`, подъём при наведении) — только у кликабельного** и только в кабинете;
  наведение — под `(hover: hover)`, «уменьшить движение» отключает сдвиги.
- **Окно поверх страницы — порталом в `body`** (`createPortal`): анимация появления оставляет на
  предке `transform`, и `position: fixed` внутри считается от блока, а не от экрана.
- **Прокручивается `.page`, и она во всю ширину окна**; ширину содержимого задаёт `--page-w`
  (отступы), а не `max-width` — иначе полоса прокрутки встаёт посреди экрана.
- Тесты кабинета — `tests/server/account.test.mjs`, как и тесты входа, только с `TEST_DATABASE_URL`.
- Проверяя письма кабинета на Mac, запускай копию **без** ключа: `PORT=3211 RESEND_API_KEY= npm run app` —
  письма печатаются в терминал. С ключом из `.env` они уходят по-настоящему.

**Онлайн-оплата (12.10) — модули: касса `cores/pay-nowpayments` (контракт `cores/PAYMENTS.md`),
граница `server/payKassa.mjs`, «дверь» `server/payments.mjs`.** Подробно — CONTEXT.md, «Онлайн-оплата». Что легко сломать:
- кредиты за оплату — **только** через `grantPackIn` в той же транзакции, что и `credited_at` заказа:
  касса повторяет уведомления, иначе двойное начисление;
- одной подписи уведомления мало — перед начислением платёж сверяется с самой кассой (`mismatch`). Не убирай сверку;
- цена счёта — только из базы по id тарифа; ничего денежного из тела запроса клиента не бери;
- адрес для кассы — `publicOrigin` (хост запроса из списка своих), не голый `req.get('host')`;
- ключи для заказа — по его признаку `sandbox`, не по текущей настройке; песочница на проде запрещена — не ослабляй;
- модуль-касса не знает про базу и кредиты и не читает окружение — ключи ему передаёт `payKassa.mjs`;
- новая касса — новый модуль `cores/pay-<id>` и строка в `payKassa.mjs`, а не правка соседней; её способы оплаты словами — в `PAY_METHODS` (`payments.mjs`), иначе в письме-подтверждении выйдет сырой код;
- **AnyPay (13.10, `cores/pay-anypay`)**: рубли касса не принимает — работает карта в сумах и гривнах (сомы — ошибка 215, скрыты); заказ у кассы — по числовому `kassa_order`, не по `id`; адрес оповещений — только в кабинете AnyPay; кнопки — по `ANYPAY_METHODS`; каждый шаг — в тему «AnyPay — журнал оплат» (`trace`); секрет проекта и API-ключ не путать. Подробно — CONTEXT.md, «AnyPay: карта в сумах и гривнах»;
- на Mac уведомление кассы не дойдёт — оплату проверяй через API песочницы (`case: success`), см. README модуля.

**Подтверждение оплаты на почту (13.10, PR #21) — `paymentMail` в `server/mailer.mjs`.** После каждого
зачисления оплаченных кредитов владельцу кабинета уходит письмо «Оплата получена». Владелец считает это
обязательным — не выключай и не теряй его при переделках оплаты. Подробно — CONTEXT.md, «Онлайн-оплата», шаг 5.
- **Два места отправки:** онлайн-оплата — `receipt` в `payments.mjs` (зовёт `credit` после транзакции);
  ручное начисление пакета менеджером — `packMail` в `accounts.mjs` (зовёт `grantPack`). Новый способ
  начислить оплаченный пакет (ещё одна касса, импорт) — тоже обязан слать это письмо.
- **Адресат — владелец кабинета** (`ownerOf`: участник `owner`, первый по времени), не тот, кто платил.
- **Письмо не ломает деньги:** только после транзакции начисления, ошибка ловится внутри. Не переноси отправку
  в транзакцию и не пробрасывай её ошибку наружу — иначе сбой Resend откатит начисление или менеджер
  начислит второй раз. Повтора отправки нет намеренно: повтор после частичной доставки — два письма.
- **Ровно одно письмо на заказ** держится на том, что `credit` доходит до отправки только у вызова,
  который сам начислил (`credited_at`). Не зови `receipt` из `apply`/`sync` по статусу `paid`.
- **Журнал:** ушло — `mail.sent` в журнале сервера и строка `mail` (с адресом) в `smmaker_payment_events`
  (миграция 014) — по номеру заказа видно, кому и когда; не ушло — `mail.failed`: онлайн — тревога «⚠️ Нужен
  человек» в тему «Оплаты» (модуль payments в «Сбои» не идёт), вручную — уровень error → тема «Сбои».
- **Валюта — из заказа** (`amount`, `currency`), способ — `PAY_METHODS`; знаки валют — `money`. Ручное
  начисление — «Стоимость: цена тарифа · оплата через менеджера» (сколько заплачено мимо кассы, мы не знаем).
  Бонусы (`grantBonus`) писем не шлют — это не оплата. Песочница — «[ТЕСТ]» в теме.
- **На превью** кнопка письма ведёт на `SMMAKER_APP_URL` — если там адрес прода, тестового заказа там нет.
  Ключ Resend на превью уводит письма на настоящие адреса из копии прода — после проверки убирай.
- Тесты: `tests/unit/paymentMail.test.ts` (валюты, ручное, песочница), `tests/server/payments.test.mjs`
  (одно письмо на заказ, сбой Resend не трогает кредиты, ручное начисление).

**Бот поддержки (`server/support.mjs`) — вебхук у бота один.** Не ставь `TELEGRAM_SUPPORT=webhook` на
превью с боевым ботом (страховка — `TELEGRAM_SUPPORT_PREVIEW`) и не вызывай `deleteWebhook` с Mac: прод
перестанет получать сообщения клиентов. На Mac — `TELEGRAM_SUPPORT=poll`, пока у бота нет вебхука прода.
Ответ клиенту — только `copyMessage` (не `forwardMessage`: он показывает автора-сотрудника).

**Ошибки и журнал — один стандарт** (12.10, CONTEXT.md «Стандарт ошибок и журнала»). Журнал —
`serverLog('<модуль>')` из `server/log.mjs`, не `console.error`: `warn` — ожидаемое, `error` — нужен
человек (уходит тревогой в Telegram, тема «Сбои»). Текст для клиента — только через `HttpError`: обычный
`Error` в ответе прячется за «Внутренняя ошибка сервера. Код для поддержки: …». Глотать ошибку
`.catch(() => {})` можно только там, где её потеря ничего не стоит (уборка временных файлов); иначе — хотя бы `warn`.

**Клиенту — «объявление», в коде — `lot`.** С 01.10 в текстах интерфейса и ошибках сервера
лот называется «объявление» (склоняется; «лот» — аукционное слово). Код, данные, адреса и
документация остаются с «лот» — не переименовывай. В палитре фото Encar «объявление» — это
объявление на Encar, поэтому своё там зовём «галерея» и «загружено», а не «в объявлении».

**KOK — только то, что видит клиент.** Название, логотипы, письма, цвета интерфейса — KOK
(`public/kok`, раздел «Бренд платформы» в CONTEXT.md). Код, база, переменные окружения —
по-прежнему SMMAKER: не переименовывай. Логотипы KOK не клади в `public/brand` — там
бренд AXIS как клиента, его берут ролики.

**Всё в базе, что наше, называется `smmaker`.** Supabase общий с kmotors и caranalizer.
Схема `smmaker` (прод) или `smmaker_dev` (Mac), таблицы и индексы — `smmaker_…`, ходим под
`smmaker_app`. Новая таблица без префикса не пройдёт `npm test`. Чужое в этом Supabase не
трогать. Схема меняется только новой миграцией `server/db/migrations/NNN_имя.sql` —
старые не правь, они уже применены. Подробно — CONTEXT.md, «База SMMAKER».

**Ролик: камера не ездит, мигание меряй числом.** Проход камеры вдоль машины владельца
укачивал — у фото только лёгкий наезд и склейки (не возвращать). Смена кадров чаще раза в
секунду при светлых и тёмных фото подряд — мигание; глазами по отдельным кадрам его не
видно. Проверяй яркость по кадрам готового файла: скачок внутри галереи ≤ ~4 за кадр.

**Фото Encar горизонтальные — рабочая копия 1500 px по высоте.** Иначе крупную полосу кадра
растягивает браузер при рендере, и фото мылится. Старые лоты пересобирает
`node tools/rebuild-photos.mjs --apply` — **после выкладки прогнать и на проде**.

**Новый формат ролика — четыре места:** `config/formats.json` (сцены на доли темпа, `short`),
`src/formats/<id>/`, строка в `src/formats/index.ts`, тексты формата во всех рынках. Реестр и
склейки проверяет `npm test`, рендер — `npm run test:render`.

**Долгое — окном, быстрое — плашкой.** Encar и сборка карусели (секунды) — `BusyModal`: экран
закрыт, `#root` — `inert`. Удаление и копия (доли секунды) — «Удаляю…» на карточке и
`toast()`. Окно на весь экран для мгновенного действия — просто мигание.

**«Поделиться» и выбор папки — только сразу после нажатия.** Safari не откроет меню
«Поделиться», если между нажатием и вызовом качались файлы, — готовь их заранее
(`usePreparedFiles`). Выбор папки (`showDirectoryPicker`) есть только в Chrome и Edge — в
остальных браузерах ZIP. Сайт не может сам положить файлы в галерею телефона.

**Карусель у машины одна, и сборка стоит кредит.** Смена формата — только отдельной кнопкой,
ссылка на уже собранную машину открывает готовую. Не делай автосборку по клику на формат.
Исключение — «Пересобрать с этой ценой» (`POST /carousels/:id/price`): бесплатно, поэтому
формат и вариант берутся из сохранённой карусели, а не из запроса — иначе через неё собирали бы
новые варианты даром. Цена на слайде — валюта профиля по курсу дня (`src/carousel/price.ts`).

**Посмотреть интерфейс без входа (агенту):** копия сервера без базы во вкладке терминала —
`PORT=3211 DATABASE_URL= npm run app`, открывается на лотах компании AXIS. После перезапуска
копии перезагрузи страницу в панели браузера: она держит в кэше модули прежнего запуска, и
проверка идёт по старому коду. Пробные лоты и карусели после проверки удаляй.
Копия без базы **пишет в `config/`**: сохранённый профиль — в `config/profiles/default.json`,
бренд (логотип, иконка) — в `config/brand.json`. Vite видит правку файла и пересоздаёт экран
(строки вроде «Загружена: …» пропадают — с базой такого нет). Проверяй правки, не сохраняя,
или откатывай: `git diff config/` после проверки должен быть пуст.

**Тесты — только по слову владельца** (11.10). Сделал → показал на :3210 → он смотрит глазами →
по его команде `npm test` / `npm run test:render` (рендер идёт 6–8 минут). Можно и выборочно:
`npx vitest run <файлы>`, `npx vitest run --project render -t "карусель"`. `tsc --noEmit` — можно всегда.

**Цена: с Encar автоматически, маржа — только «Ценой в ролике».** Концепция владельца (11.10):
цена авто приходит с Encar и сама пересчитывается в валюту профиля по курсу дня; клиент
незаметно закладывает маржу, вписывая свою итоговую цену (`lot.priceOverride`, у карусели —
`priceOverride` в `carousel.json`). Полей «цена авто / курс / сразу $» в объявлении больше
нет — не возвращай без запроса. В ролик и на слайд не выводи ничего, что раскрывает расчёт
(курс, «с наценкой»). Не округляй — круглую цену клиенты вписывают сами.

**Цену объявления на экране считай через `lotTotal`, не `totalInCurrency`.** Рендер получает
рынок целиком (`resolveAd`), а экран собирал поля сам и забыл курс дня: при ₽ форма писала

(экраны) как `market.krwPerUnitToday` — новый экран с ценой оборачивай в `useTodayMarket`.

**Валюта — только из списка `src/shared/currencies.js`.** Свободное поле давало «РУБЛЬ» в ролике.

Новая валюта — строка в `CURRENCIES`; курс к ней придёт сам из того же ответа open.er-api.

**Тексты компании лежат по языкам: `profile.texts[язык]`.** Читай через `textsForLanguage` —
старые профили хранили плоскую пачку без языка. Пустое поле = текст по умолчанию; скрыть
надпись пустой строкой нельзя. Поля в «Реклама авто» разложены по сценам (`AD_SCENES` в

**Encar — тоже ядро** (12.10): `cores/encar` (через шлюз kmotors), граница `server/encar.mjs`

**Источники — независимые модули-ядра** (решение владельца 11.10): `cores/<id>` внутри KOK,
логикой не пересекаются (Encar, Китай, Япония; отдельно — распознавание ссылки, карусели, ролики).
Вызов — прямым импортом точки входа, контракт — `cores/CONTRACT.md`. **Не делай ядра отдельными

## Правило про комментарии

Комментируй **почему**, а не «что». «Увеличиваем счётчик» писать не надо — видно и так.
А вот почему тут `Math.floor`, а не `round`, почему цифра именно 0,12 и что сломается, если
её поменять, — надо: через месяц это неочевидно даже автору.

Особенно комментируй: подобранные на замерах числа (с самим замером), обходы чужих
странностей, и места, где очевидное решение неверно — с объяснением, почему.

## Что не коммитить

`data/` (исходники, копии, рендеры), `.env`, `.venv-demucs`. Всё уже в `.gitignore` —
проверяй, что не добавил лишнего: одна команда `git add -A` уже затаскивала 5 МБ мусора.
