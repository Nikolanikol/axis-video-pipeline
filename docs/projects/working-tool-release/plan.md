# Рабочий инструмент KOK — подготовка релиза

План от 19.11.2026 по аудиту интерфейса и реальным генерациям. Пользователь поручил
выполнять работу последовательно, по этапам. Витрина и блог в эту работу не входят.

## Цель

Клиент на компьютере и телефоне может подготовить материал, заранее понять стоимость,
получить файл и вернуться к своей работе без новой генерации и потери правок.

закрытие всех улучшений за один день не предполагается.

## Что сохраняем

- Живые превью и оформление; компоновку управления меняем после просмотра макета.
- Автосохранение объявлений и уже реализованные действия с готовыми роликами.
- Общую форму КП и единую вёрстку превью/PDF: [устройство КП](../../app/offers.md).
- Работающий поиск объявлений и каруселей: добавлять его заново не требуется.
- Закрытые обзоры до отдельной приёмки их тяжёлого сценария.

Цена КП для бесплатной роли исправлена при адаптации этапа 5: у сотрудника кнопка без
указания списания. Остальные задачи этапа 6 этим не закрываются.

## После стабилизации основных сценариев

- Рабочий стол с последней машиной, недавними результатами и заданиями.
- История нескольких версий/форматов карусели. До неё — ясное предупреждение о замене
  текущей версии и доступ к скачиванию перед заменой.
- Общая библиотека результатов по машине.

Это отдельные изменения после обязательных исправлений, а не условия начала работы.

## Проверка каждого этапа

1. Воспроизведение на конкретных входных данных и фиксация причины.
2. Локальное исправление в ветке этапа, проверка типов и ручной проход затронутого пути.
3. Для интерфейса — компьютер 1280×720 и 1440×900, телефон 360/375/390 px; после изменения
   раскладки проверяем отсутствие горизонтального переполнения. Физические Safari/iPhone
   и Chrome/Android проверяются отдельно, эмуляция их не заменяет.
4. Критичные состояния: пусто, заполнено, ожидание, успех, ошибка, возвращение после ухода.
   Для админки дополнительно проверяем большой список, длинные имена и переходы страниц;
   для входа — доступность пароля и понятный пример телефона без изменения правил номера.
5. Автотесты запускаются после команды владельца, как предписывает `CLAUDE.md`.
6. Запись результата в [journal.md](journal.md), затем проверка владельцем и превью по
   принятому в проекте порядку. Коммит, push, PR и merge — по отдельной команде владельца.

## Дополнительные условия приёмки

- Платная клиентская роль проверяется отдельно от бесплатного владельца.
- Проверки базы используют изолированную тестовую базу; применённые миграции не меняются.
- Для che168 и Carsensor нужен положительный импорт свежих доступных объявлений.
- Платежи и письма проходят тестовый сценарий; реальные сообщения клиентам в этот план
  автоматически не входят.
- Известная в [pitfalls.md](../../app/pitfalls.md) гипотеза об обходе изоляции файлов
  проверяется локально с включённым входом; подтверждённая утечка блокирует релиз.
- Корневая причина сбоя и факт исправления подтверждаются отдельно от статуса «Done».
