# Ядра источников — общий контракт

Ядро — **независимый модуль внутри KOK**, который забирает машину с одного сайта (Encar, Китай,
Япония, …) и отдаёт её в стандартном виде. Архитектура приложения (решение владельца 11.10):
отдельные модули, которые логикой не пересекаются, — модули источников (`cores/<id>`), модуль
распознавания ссылки (какой это сервис), модуль каруселей, модуль рекламных роликов. KOK знает
только этот контракт: как ядро достаёт данные внутри — его личное дело.

Этот файл — закон для каждого нового ядра. Меняешь контракт — меняй все ядра и версию контракта.

**Версия контракта: 2** (11.10.2026; в версии 1 ядра были отдельными HTTP-сервисами — отменено)

## 1. Независимость

- **Ядро — папка `cores/<id>/` в репозитории KOK**, вызывается прямым импортом точки входа.
  Отдельных приложений, процессов и портов у ядер нет — выкатываются вместе с KOK.
- **Ядра не импортируют друг друга** и не знают про карусели, ролики и интерфейс. Общее у всех
  ядер — только `cores/kit/` (ошибки, логи, ограничитель запросов).
- **Наружу из ядра выходят только `CoreError`** (раздел 3) — любое чужое исключение ядро само
  заворачивает в `INTERNAL`. Граница модуля в KOK (`server/<id>.mjs`) переводит код в ответ
  интерфейсу; ошибка одного ядра не задевает другие источники.
- Без внешних зависимостей, если можно (che168 — только Node 20+). Зависимость — осознанно и в README.
- Свой `README.md` «как работает»: откуда данные, какие запросы, поля, где легко ошибиться,
  на чём проверено.

## 2. Точка входа — `src/index.mjs`

```js
export const core = { id, title, version, contract: 2, languages: {supported, default}, refExamples };
export async function getCar(ref, { langs, log, signal }) // → { data, warnings } или бросает CoreError
export async function checkUpstream({ signal })            // → { ok, ms } или бросает CoreError
```

`ref` — ссылка или номер; `signal` — общий таймаут вызывающего (KOK даёт 45 с); `log` — логгер
с `requestId` запроса. KOK (`server/<id>.mjs`) и CLI ядра (`bin/fetch.mjs`) зовут только это.

## 3. Конверт и ошибки

Успех — `{ data, warnings: [{ code: "PART_MISSING", part: "options", message: "…" }] }`.

Ошибка — `CoreError` (`cores/kit/errors.mjs`): `{ code, message, retryable, details?, status }`.
Где нужен конверт (CLI ядра, будущие API), он один: `{ok, core, version, requestId, tookMs, warnings, data}`
или `{ok: false, …, error: {code, message, retryable, details}}` — `errorPayload()` в kit.

`code` — для программы (одинаковые во всех ядрах), `message` — по-русски для человека,
`retryable` — есть ли смысл повторить позже. Пайплайн решает по `code`, текст показывает как есть.

| code | статус в KOK | retryable | когда |
|---|---|---|---|
| `BAD_INPUT` | 400 | нет | не ссылка этого источника, нет номера, неизвестный язык |
| `NOT_FOUND` | 404 | нет | машины нет: продана, снята, неверный номер |
| `RATE_LIMITED` | 429 | да | источник просит притормозить |
| `UPSTREAM_BLOCKED` | 503 | нет | источник закрыл доступ (403, проверка на бота) — нужен человек |
| `UPSTREAM_TIMEOUT` | 504 | да | источник не ответил вовремя |
| `UPSTREAM_UNAVAILABLE` | 502 | да | сеть, DNS, 5xx источника |
| `UPSTREAM_BAD_RESPONSE` | 502 | нет | источник ответил, но не тем: не JSON, поменялся формат — **чинить ядро** |
| `OVERLOADED` | 503 | да | в ядре слишком много запросов разом |
| `INTERNAL` | 500 | нет | ошибка в коде ядра — **чинить ядро**, подробности в логе по `requestId` |

**Частичные данные — не ошибка.** Нет опций, листа осмотра, одного фото — карточка отдаётся,
а в `warnings` строка с `code` (`PART_MISSING`, `PART_FAILED`) и `part`. Ошибка — только когда
без этой части машины нет (основная карточка).

## 4. Карточка (`data`)

Обязательно в каждом ядре:

```
source        id ядра («che168»)
ref           номер машины у источника (строкой)
fetchedAt     ISO-время
urls          { … } ссылки на объявление
price         { amount, currency, …свои поля } — валюта ISO (USD, KRW, JPY, CNY)
mileageKm
photos[]      { url — оригинал, category, angle?, ad?, source }
              category: exterior | interior | engine | detail | underbody | document | unknown
              ad: false — в рекламу не брать (наклейки, ключи, шины…); source — откуда роль:
              studio (точно по порядку съёмки) | position (догадка по положению) | model (распознавание)
byLang.<язык> { car: { title, brand, series, trim, … }, …свои разделы }
```

Остальное — своё у каждого источника и описано в его README. В стандарт KOK (`CarouselCar`)
карточку переводит переходник на стороне пайплайна, по одному на источник.

## 5. Устойчивость — обязательный минимум

- **Ядро не роняет KOK.** Всё внутри `getCar` в `try/catch`, любое чужое исключение → `INTERNAL`
  + запись в лог со стеком. Никаких глобальных обработчиков процесса — это дело KOK.
- **Таймаут на каждый запрос к источнику**, общий — сигнал вызывающего (`signal`).
- **Повторы только для `retryable`**, не больше 3, с паузой; `NOT_FOUND` и `BAD_INPUT` не повторяем.
- **Ограничение параллельных запросов к источнику** — бережём источник и свой IP от блокировки.
  Очередь переполнена — `OVERLOADED`, а не бесконечное ожидание.
- **Разбор ответа не доверяет форме**: любое поле может пропасть или сменить тип. Падение разбора —
  `UPSTREAM_BAD_RESPONSE` с указанием, какая часть, а не `TypeError` наружу.

## 6. Логи

Одна строка JSON на событие в stdout (Coolify собирает сам):

```json
{"ts":"2026-10-11T12:00:00.000Z","level":"info","core":"che168","event":"car.ok","requestId":"…","ref":"60154824","tookMs":412}
```

`level`: `info` — штатное, `warn` — частичные данные, повторы, ожидаемые ошибки (`NOT_FOUND`,
`BAD_INPUT`), `error` — `INTERNAL`, `UPSTREAM_BAD_RESPONSE`, `UPSTREAM_BLOCKED` и всё со стеком.
`requestId` задаёт граница модуля в KOK и передаёт логгером (`log.child({requestId})`) — по нему одна
операция ищется в логе целиком.

## 7. Новое ядро — чек-лист

1. `cores/<id>/` по образцу che168: `src/index.mjs` (точка входа), `src/upstream.mjs` (сеть → коды),
   `src/parse.mjs` (разбор, чистые функции), `bin/fetch.mjs` (CLI для проверки), `README.md`.
2. Граница в KOK — `server/<id>.mjs` (вызов + CoreError → HttpError + логи) и переходник в
   `CarouselCar` — `src/shared/<id>Car.js`. Распознавание ссылки — в модуле ссылок (`src/shared/encarLink.js`).
3. Разведка источника → README ядра: откуда данные, запросы, поля, ловушки.
4. Проверка ошибок руками: неверная ссылка, несуществующая машина, источник недоступен
   (`<ID>_API_BASE` на мёртвый адрес), таймаут — у всех правильный `code`, KOK жив.
5. Проходка на 10+ разных машинах, итоги в README.
