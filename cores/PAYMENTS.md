# Модули-кассы — общий контракт

Касса — **независимый модуль внутри KOK**, который принимает деньги через одного платёжного
провайдера (NOWPayments, AnyPay, …). Устроена по тем же правилам, что ядра источников
(`cores/CONTRACT.md`): папка `cores/pay-<id>/`, вызов прямым импортом, наружу — только `CoreError`
из `cores/kit`, логи — строкой JSON. Кассы не импортируют друг друга и не знают про кредиты,
тарифы, базу и интерфейс — это дело KOK (`server/payments.mjs`, «дверь» оплаты).

Этот файл — закон для каждой новой кассы. Меняешь контракт — меняй все кассы и версию.

**Версия контракта: pay-1** (12.10.2026)

## 1. Независимость

- Папка `cores/pay-<id>/`: `src/index.mjs` (точка входа), `src/upstream.mjs` (сеть → коды),
  свои чистые модули (подпись, статусы), `bin/check.mjs` (проверка руками), `README.md`.
- **Ключи касса из окружения не читает** — их передаёт KOK в `createClient`. Так один процесс держит
  боевой и тестовый клиент, а тесты не трогают переменные.
- Без внешних зависимостей (только Node 20+).

## 2. Точка входа — `src/index.mjs`

```js
export const core = { id, title, version, contract: 'pay-1', payCurrency, priceCurrency };
export function createClient({ apiKey, ipnSecret, sandbox }) → {
  sandbox, ready,
  createInvoice({ orderId, amount, description, notifyUrl, returnUrl }) → { invoiceId, url }
  getPayment(paymentId)                → Payment
  readNotification(body, signature)    → Payment   // подпись проверена; неверная — BAD_INPUT
  checkUpstream()                      → { ok, ms, … }
}
```

## 3. Платёж в общем виде (`Payment`)

```
provider       id кассы («pay-nowpayments»)
paymentId      номер платежа у кассы (строкой)
invoiceId      номер счёта у кассы или null
orderId        НАШ номер заказа — по нему KOK находит заказ
status         waiting | confirming | paid | partial | failed | expired | refunded | unknown
providerStatus слово кассы как есть — для журнала
priceAmount, priceCurrency   сумма и валюта счёта
payAmount, payCurrency       сколько и чем должен заплатить клиент
actuallyPaid   сколько пришло (песочница NOWPayments пишет 0 даже у оплаченного)
```

`paid` — единственный статус, после которого KOK начисляет. `unknown` — касса сказала незнакомое
слово: не начислять, писать в лог.

## 4. Ошибки

Коды — из `cores/kit/errors.mjs`, смысл для касс:

| code | когда |
|---|---|
| `BAD_INPUT` | неверная подпись уведомления; касса отказала по сути (сумма меньше минимальной, монета выключена) |
| `NOT_FOUND` | касса не знает платежа |
| `UPSTREAM_BLOCKED` | ключ не принят или касса не настроена — **нужен человек** |
| `RATE_LIMITED`, `UPSTREAM_TIMEOUT`, `UPSTREAM_UNAVAILABLE` | временно: повторить позже |
| `UPSTREAM_BAD_RESPONSE` | касса ответила не тем — **чинить модуль** |
| `OVERLOADED` | в модуле слишком много запросов разом |
| `INTERNAL` | ошибка в коде модуля |

Повторы — только у запросов на чтение. **Выставление счёта не повторяется**: оборванный ответ при
повторе дал бы второй счёт, о котором клиент не знает.

## 5. Безопасность — обязательный минимум

- **Подпись уведомления** проверяется за постоянное время; пустой секрет — подпись всегда неверна.
- **Уведомлению одному не верить.** Модуль только читает его; KOK перед начислением обязан спросить
  платёж через `getPayment` и сверить заказ, сумму, валюту счёта и монету. Подпись защищает от чужих
  уведомлений, сверка — от ошибки в нашей проверке подписи и от утёкшего секрета уведомлений.
- Ключи и секреты не попадают ни в логи, ни в ответы, ни в `details` ошибок.
- Номер заказа уходит кассе только латиницей и цифрами: он возвращается в уведомлении и ищется в базе.

## 6. Новая касса — чек-лист

1. `cores/pay-<id>/` по образцу `pay-nowpayments`, свой README: как работает касса, статусы, подпись,
   ловушки, на чём проверено.
2. В KOK: `provider` в `smmaker_payments` (CHECK в миграции), клиент в `server/payKassa.mjs`, адрес
   уведомлений `/api/payments/<id>/notify`.
3. Проверить руками: верная и неверная подпись, повтор уведомления, недоплата, касса недоступна
   (`bin/check.mjs` с неверным ключом), полная оплата в песочнице.
