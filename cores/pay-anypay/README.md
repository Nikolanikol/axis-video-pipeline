# Касса AnyPay — карта (сумы, гривны; рубли — когда откроют) и СБП

Модуль-касса KOK по контракту `cores/PAYMENTS.md` (версия pay-1). Задумана для рублей (СБП, карта РФ) через
[AnyPay](https://anypay.io), но рубли касса пока не принимает — работает карта P2P в сумах (UZS) и гривнах (UAH);
валюта счёта — параметр `currency` у `createInvoice`, допустимые пары — `core.currencies`. Не знает про кредиты,
тарифы и базу — только API кассы. Что делать с деньгами, решает KOK: `server/payments.mjs`.

Справка по самой кассе (параметры, подписи, статусы, коды ошибок, настройки кабинета) — `ANYPAY.md`.

## Почему AnyPay (решение владельца 12.10.2026)

Владелец — физлицо в Южной Корее без российского номера и ИП, клиенты — в основном из РФ. Российские
кассы требуют российский статус. AnyPay принимает рубли (карты, СБП) и выводит в USDT TRC20. Риски —
в `CONTEXT.md` и памяти проекта: юрлицо оператора не названо, выводить часто.

## Как идёт оплата

1. KOK заводит заказу **числовой** номер у кассы (`pay_id`: цифры, до 15 знаков) и вызывает
   `createInvoice({orderId, amount, description, email, method, returnUrl})` → API `create-payment`.
   Счёт — в рублях, способ (`sbp`/`card`) клиент выбрал у нас. Ответ — `payment_url` (страница кассы)
   и `transaction_id` — номер платежа у кассы, известен сразу.
2. Клиент платит. Касса шлёт оповещение на «URL оповещения» **из кабинета** (не из запроса) —
   `https://<сайт>/api/payments/anypay/notify`, POST.
3. KOK проверяет IP (`isKassaIp`), читает оповещение `readNotification(body)` — проект и подпись — и
   перед начислением спрашивает платёж у кассы `getPayment(transaction_id)` → API `payments`.
   Ответ кассе — текст `OK`, иначе она повторяет (если в проекте включено «Подтверждение платежа»).

## Подписи — две разные

- **Оповещение**: `sha256("currency:amount:pay_id:merchant_id:status:СЕКРЕТ")`, через `:`, секрет —
  «Секретный ключ» проекта. `merchant_id` — наш, из настроек. Значения — строками как пришли.
  В кабинете должен стоять алгоритм **SHA256** (MD5 модуль не принимает).
- **Запрос к API**: `sha256("<метод>" + API_ID + параметры + API_KEY)`, **без разделителей**, ключ —
  API-ключ из профиля.

Перепутать секрет проекта и API-ключ — главная ловушка: касса ответит «Invalid sign» (102) на всё.

## Ошибки

| что случилось | код | повтор |
|---|---|---|
| 101–104, 200, 201, 310 — ключи, подпись API, API выключен, IP, проект | `UPSTREAM_BLOCKED` | нет, нужен человек |
| 105 — слишком часто | `RATE_LIMITED` | да |
| 215, 309 — сбой у кассы | `UPSTREAM_UNAVAILABLE` | да (чтение) |
| 204/205 — сумма вне лимитов, 208 — способ недоступен, прочие 2xx/3xx | `BAD_INPUT`, `details.kassaCode` | нет |
| сеть, DNS, 5xx | `UPSTREAM_UNAVAILABLE` | да (чтение) |
| таймаут 20 с | `UPSTREAM_TIMEOUT` | да (чтение) |
| ответ без `result` | `UPSTREAM_BAD_RESPONSE` | нет — чинить модуль |

Ошибку касса присылает телом `{"error": {"code": "102", …}}`, как правило с HTTP 200 — смотрим тело.
Создание платежа не повторяется никогда.

## Ловушки

- **Песочницы нет.** Тестовое оповещение — кабинет → проект → «Тестирование», приходит с `test=1`
  (`payment.test`). Начислять по нему или нет, решает KOK.
- **Адрес оповещений один на проект и ведёт на прод.** На Mac оповещение не дойдёт; превью — только
  если на время поставить его адрес в кабинете (ANYPAY.md, «Тестовое оповещение»).
- `success_url`/`fail_url` из запроса работают, только если в проекте «Переопределять URL» → «Разрешено».
- Ответ `commissions` на деле вложенный и строками, пустой список платежей — `null` (не `{}`).

## На чём проверено (13.10.2026)

С Mac, боевые ключи: `bin/check.mjs` — связь, баланс, комиссии; неизвестный платёж — `NOT_FOUND`; неверный
API-ключ — `UPSTREAM_BLOCKED` (102). Создание платежа: RUB (`sbp`, `card`) — 208, способ неактивен; карта в
**UZS и UAH — ссылка выдаётся**, KGS — всегда 215. Живой оплаты и настоящего оповещения ещё не было. Весь путь
«заказ → оповещение → сверка → кредиты» — автотестом `tests/server/paymentsAnypay.test.mjs` (касса подменена).
Модуль — `tests/unit/payAnypay.test.ts`.
