# Ядро рассылок (`cores/mailing`)

Служебные новости KOK клиентам: новые функции, изменения, плановые работы. **Не реклама**
(решение владельца 21.10). Ядро собирает письмо и отправляет его пачками через Resend — тот же
аккаунт и тот же отправитель, что у писем входа и оплаты (`mail.axis-beauty.com`).

## Что ядро знает и чего не знает

| ядро (`cores/mailing`) | KOK (`server/mailing.mjs`) |
|---|---|
| вёрстка письма, подстановки `{имя}` `{компания}`, текст → HTML | кому слать: сегмент (фильтры админки), согласие, отписка, скрытые |
| проверка черновика (`problemsOf`) | черновики и рассылки в базе (`smmaker_mailings`) |
| отправка пачкой и по одному, заголовки отписки | очередь, паузы, «ушло / отказ» по каждому получателю |
| коды ошибок Resend → `CoreError` | что делать с ошибкой: подождать, остановить, тревога |

Ядро не читает окружение и не ходит в базу: ключ и отправителя передаёт KOK в `createClient`.

## Точка входа — `src/index.mjs`

```js
export const core = { id: 'mailing', version, contract: 'mail-1', batchMax: 100 };
export function createClient({ apiKey, from, replyTo }) → {
  ready,                    // false — нет ключа: KOK пишет письма в журнал вместо отправки
  sendBatch(messages) → [id]   // до 100 писем; одно плохое — отказ всей пачки (BAD_INPUT)
  send(message) → id
}
export renderMessage({ subject, body, button, vars, brand, unsubscribeUrl }) → { subject, html, text }
export problemsOf({ subject, body, button }) → ['проблема словами', …]
export PLACEHOLDERS, fill, textToHtml, isHttpUrl
```

`message` = `{ to, subject, html, text, unsubscribeUrl }`.

## Разметка текста

Нарочно бедная: абзац — пустая строка, перенос — Enter, `**жирный**`, ссылки `https://…`
становятся ссылками сами. Одна кнопка — подпись и ссылка отдельными полями. Картинок нет:
сложная вёрстка чаще уходит в спам.

## Где легко ошибиться

- **Повторов нет намеренно.** Повтор после оборванного ответа — два письма у клиента. Временный
  сбой (`retryable`) KOK переживает паузой в очереди, а не повтором того же запроса.
- **Заголовки `List-Unsubscribe` + `List-Unsubscribe-Post` обязательны.** Без них Gmail режет
  массовые письма. Ссылка отписки в заголовке и внизу письма — одна.
- **Ссылка отписки — по случайному ключу человека** (`news_key`), не по почте и не по id: иначе
  пересланное письмо позволяло бы отписать кого угодно.
- **Лимиты Resend:** запросов в секунду (по умолчанию 2) и писем в день/месяц по тарифу. Пачка — один
  запрос до 100 писем; KOK шлёт пачки с паузой. 429 — `RATE_LIMITED`, очередь ждёт и продолжает.
- **Неизвестная подстановка** (`{имяя}`) уйдёт клиенту как есть — `problemsOf` не даёт отправить.

Проверено: `tests/unit/mailingCore.test.ts` (вёрстка, подстановки, проверка черновика, пачка и
отказы Resend на подменённом `fetch`).
